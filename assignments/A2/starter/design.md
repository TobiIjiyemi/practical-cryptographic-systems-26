Transcript hash is generated by hashing (with SHA 256) prefix message "JMessage-2026" along with an encoding of the bytes of the initiator name , responder name, complete hello bytes and complete reply bytes. Both the responder and the initiator compute the same hash to ensure on both sides it's the initiator sneding bytes to the responder and the responder sending bytes to the initiator.

Key-Derivation is made from using the Hashing key derivation function with SHA256 as the hash, a prefix message and suite selection as info, length input, and salted with the transcipt hash from above. Diffie hellman exchange is used as input keying material for the key derivation and the output of the function is the keys that will be used for encrypting and decrypting the data. 

Record-processing has a whole bunch of checks like the state in which the session is in. If a connection isn't established then the record isn't processed, if sid from the record isn't found then terminate record processing. Make sure that the sequence number from the record is equal to the receive sequence number stored in the session. Derive the keys depending on the suite, compose the nonce and associated data and then try decrypting the record using the keys , nonce, and associated data.
